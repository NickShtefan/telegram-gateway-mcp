# tg-mcp

MCP-шлюз к Telegram. Один демон держит сессии подключённых аккаунтов Telegram и отдаёт их агентам (Claude Code, Hermes, Codex, OpenCode, любой MCP-клиент) как набор инструментов: чтение каналов, групп и комментариев, поиск, выгрузка в файл, картинки, поиск каналов, статистика, локальный индекс и запись с подтверждением.

Шлюз это инструмент для агента, а не агент (решение 25). Он ничего не делает, пока агент не вызвал инструмент: не следит за чатами, не запускает модели, не ведёт задач. Внутри нет модели и API-ключей. Сводки, расчёты и тексты делает агент; следить за каналом или вести переписку он тоже может сам, своим расписанием и своей памятью.

## Что умеет

23 инструмента в пяти наборах. Наборы включаются переменной `TG_MCP_TOOLSETS`, по умолчанию только `core`.

| Набор | Инструменты | Что даёт |
|---|---|---|
| `core` | `tg_status`, `tg_list_dialogs`, `tg_resolve`, `tg_search_messages`, `tg_search_chat`, `tg_read_history`, `tg_get_message`, `tg_get_comments`, `tg_list_topics`, `tg_export`, `tg_get_media` | чтение и поиск: чаты аккаунта, карточка чата, лента, комментарии, темы форумов, выгрузка в JSONL или CSV, фото и альбомы |
| `discover` | `tg_find_channels`, `tg_similar_channels`, `tg_forward_sources` | поиск каналов по названию, похожие каналы, источники репостов |
| `analytics` | `tg_channel_stats` | числа по каналу: подписчики, охват, вовлечённость, тренд |
| `index` | `tg_index`, `tg_local_search` | локальный индекс чата и поиск по нему без запросов к Telegram |
| `write` | `tg_reply`, `tg_send`, `tg_react`, `tg_join`, `tg_press_button`, `tg_confirm` | ответ в комментариях, сообщение, реакция, вступление, нажатие кнопки бота: только в два шага |

Подробно: [docs/tools.md](docs/tools.md).

## Главные свойства

- **Один процесс на сессии.** Демон слушает `127.0.0.1`, каждый пользователь шлюза ходит со своим bearer-токеном и видит только свои и общие аккаунты.
- **Запись в два шага.** Инструмент записи возвращает предпросмотр и `approval_id`; в Telegram действие уходит только после `tg_confirm`, который агент вызывает после согласия владельца.
- **Личные чаты закрыты.** Открывает их владелец командой: один диалог, только отправка или чтение и отправка. Служебные чаты Telegram закрыты всегда.
- **Чужой текст помечен.** Всё, что написано в Telegram, в ответах обёрнуто в метки: это данные, а не команды агенту.
- **Бережное отношение к аккаунту.** Каждый вызов MTProto идёт через очередь аккаунта с дедлайном; FLOOD_WAIT возвращается агенту как ошибка с `retry_after`; у записи дневные пределы.
- **Всё состояние в одном файле SQLite.** Внешних сервисов нет.

Как это устроено внутри: [docs/architecture.md](docs/architecture.md).

## Состояние

- Установлен на лабораторной машине `macbook-pro-lab.local` под отдельным пользователем macOS, подключён к Claude Code и Hermes. Пользуются двое, владелец и жена владельца: у каждого свои аккаунты Telegram, есть общие.
- Чтение проверено на живом Telegram во всех наборах. Запись: сообщение человеку, ответ под постом и реакция выполнены на живом Telegram; вступление проверено до предпросмотра.
- Репозиторий приватный (`telegram-gateway-mcp`), в npm не публикуется. `npx tg-mcp` не запускать: в npm под этим именем чужой пакет.

Подробно: [docs/plan.md](docs/plan.md).

## Быстрый старт для разработки

```bash
npm ci && npm run build && npm test
```

```bash
node dist/cli/index.js help
```

Состояние лежит в `~/.tg-mcp` (или в `TG_MCP_HOME`). Учётные данные приложения Telegram кладутся в `<папка>/.env` как `TG_API_ID` и `TG_API_HASH`.
