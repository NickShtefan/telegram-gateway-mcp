# Кейсы

Задачи, под которые проектируется шлюз. Их назвал владелец 1 октября 2026. Пошаговый проход каждого кейса через компоненты: [scenarios.md](scenarios.md).

Кейсы бывают двух видов:

- **Разовый запрос**: агент решает задачу за один разговор, шлюз только отвечает на вызовы.
- **Постоянная задача**: шлюз работает, пока агент не запущен, сам замечает события и будит агента. Внутри два подвида: **правило** реагирует на событие и забывает его, **поручение** помнит цель и переписку до результата.

## 1. Цены в барахолке (разовый запрос)

> «Зайди в чат барахолки, найди объявления на такую-то тему и дай аналитику по ценам»

Цепочка: `tg_resolve` → `tg_list_topics` → `tg_search_chat` → `tg_export (photos=thumb)` → код агента → `tg_get_media`

Что нужно шлюзу:

- **Темы форумов.** Барахолки часто разбиты на «Продам», «Куплю», «Обмен»; поиск, лента и выгрузка принимают `topic`.
- **Выгрузка в файл.** Сотни объявлений не влезут в контекст. `tg_export` пишет JSONL и возвращает путь, число строк и пять примеров; медиану и разброс агент считает своим кодом.
- **Разбор цен при выгрузке:** «25к», «25 000 ₽», «$300», «торг», тип объявления (продам или куплю). Авторы хэшируются, телефоны маскируются.
- **Фото объявлений:** превью пачкой вместе с выгрузкой, полный альбом по запросу, чтобы агент оценил состояние вещи.
- **Закрытые чаты:** вступление только через шлюз записи с подтверждением. Капчу бота-привратника проходит владелец, не агент.

## 2. Сводка по каналу (разовый запрос)

> «Зайди на этот канал и расскажи, о чём там говорят»

Цепочка: `tg_resolve` → `tg_read_history (brief)` → `tg_get_message × 5` → `tg_get_media` → `tg_get_comments × 5`

Что нужно шлюзу:

- **Краткий режим ленты:** 1-2 строки на пост плюс просмотры, реакции и число комментариев. Месяц постов укладывается в несколько тысяч токенов.
- **Комментарии** самых обсуждаемых постов, отсортированные по реакциям (код чтения треда есть в helper).
- **Картинки постов**, когда главное на графике или скриншоте.
- **Пометка чужого текста:** в комментариях бывают попытки командовать агентом.

## 3. Мониторинг и ответы в комментариях (правило)

> «Следи за этим каналом и, когда выходят посты, отвечай на них в комментариях»

Цепочка: `tg_rule_set` → `tg_confirm` → наблюдатель → запуск агента → `tg_reply` → `tg_inbox` у агента владельца → `tg_confirm`

Что нужно шлюзу:

- **Любой канал** (решение 15): агент сам добавляет и убирает наблюдаемые чаты через `tg_watch`, без подтверждения; подтверждения требуют только ответы.
- **Наблюдатель** за новыми постами: быстрый слой (обновления GramJS, для своих каналов можно Bot API) плюс сверка по расписанию, как в helper. Переживает рестарт без дублей и пропусков.
- **Правило с лимитами:** один ответ на пост, N в день, тихие часы, случайная задержка, пропуск рекламы.
- **Запуск агента без владельца:** `claude -p`, `codex exec` или `opencode run` с токеном, который открывает только этот пост и один ответ в его ветке.
- **Подтверждение:** черновик ответа ждёт владельца. Его агент показывает черновик и после «да» вызывает `tg_confirm`; текст можно заменить своим. Отдельного бота нет (решение 23). Агент, запущенный по правилу, подтвердить ответ сам не может.
- **Ответ в ветку** через `messages.getDiscussionMessage` и `sendMessage`, от подключённого аккаунта или от имени канала (`send_as`), если аккаунт админ.

## 4. Переписка и договорённость (поручение)

> «Напиши такому-то аккаунту и договорись с ним о том-то»

Цепочка: `tg_task_start` → `tg_confirm` → ответ собеседника → `tg_task_get` → `tg_send` (ждёт `tg_confirm`) или вопрос владельцу → `tg_task_update`

Что нужно шлюзу:

- **Поручение с памятью:** собеседник, цель, рамки своими словами, срок, лимит сообщений, вся переписка и состояние (черновик, ждём ответ, агент думает, вопрос тебе, готово, закрыто). Агент между запусками ничего не помнит, помнит шлюз.
- **Список того, что решает только владелец:** выход за рамки, деньги, адрес, личные данные, время встречи. На этом агент переводит поручение в «вопрос тебе».
- **Вопросы и отчёты во входящих** (`tg_inbox`): их передаёт владельцу его агент. Ответ владельца агент записывает через `tg_task_update state=answer`, и он уходит агенту поручения как указание.
- **Токен только на один диалог,** лимит новых диалогов в день, одно напоминание, если собеседник молчит сутки.
- **Честное представление:** в первом сообщении агент по умолчанию говорит, что пишет как помощник.
- **Пишет подключённый аккаунт** (решение 9): аккаунт агента или личный аккаунт владельца, если он его подключил. Способ через Business-бота снят решением 23.
- **Переводов денег агент не делает никогда.**

## Общее требование: изображения

Скачивать картинки для анализа во всех кейсах: фото, альбом целиком по `grouped_id`, превью видео; размер `thumb` по умолчанию и `full` по запросу; путь к файлу или image-контент в ответе для клиентов, которые его принимают. Картинки дорогие для модели, поэтому по умолчанию превью.

## Общее требование: несколько пользователей

Шлюзом пользуются владелец и жена владельца, каждый из своей сессии Claude Code. У каждого свои аккаунты Telegram, есть общие. Шлюз узнаёт пользователя по токену, даёт ему только его и общие аккаунты; свои запросы на запись каждый подтверждает сам, через своего агента (решения 16 и 23).

## От чьего имени пишет агент (решено)

Пишет тот аккаунт, который подключён к шлюзу: отдельный аккаунт агента или личный аккаунт владельца, если он сам его подключил. В канале, где аккаунт админ, можно писать от имени канала (`send_as`). В правиле и поручении аккаунт указывается явно.
