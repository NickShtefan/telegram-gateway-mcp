# Инструменты MCP

Контракт, который видит агент. Наборы включаются переменной `TG_MCP_TOOLSETS` (по умолчанию `core`). Точные схемы аргументов и описания: `src/mcp/tools/`. Этот файл описывает назначение; при расхождении прав код.

## Правила контракта

- Только tools; resources, prompts и elicitation не используются.
- Плоские JSON-схемы: строки, числа, boolean, enum и массивы из них. Без union, `anyOf` и вложенных объектов. Это проверяется тестом.
- Имена `tg_*` в snake_case. В `core` одиннадцать инструментов: описания всех попадают в контекст агента.
- Аннотации: `readOnlyHint` для чтения, `destructiveHint` для записи.
- Ответ компактным текстом: одна строка заголовка на сообщение (id, дата, автор, счётчики, ссылка t.me), текст обрезан до лимита, в конце `next_cursor`. `structuredContent` не отдаётся (решение 20).
- Ошибки: `isError` с текстом `Error: КОД`, объяснением и `retry_after` для FLOOD_WAIT.
- Долгое оформляется задачей: `tg_export` ждёт до 20 секунд и возвращает `job_id`.
- Текст из Telegram всегда помечен как чужой: блок между `<<<TG:метка` и `TG:метка>>>` или строка с `> `. Метка случайная для каждого ответа.
- Даты в аргументах: `30d`, `12h`, `2w`, `2026-09-01` или ISO. Время в ответах UTC.
- Вызов идёт от пользователя, которого шлюз узнаёт по bearer-токену. У инструментов, которые ходят в Telegram, необязательный параметр `account`: по умолчанию аккаунт пользователя, доступны только свои и общие аккаунты (решение 16).
- `tg_status` доступен при любом составе наборов.

## Запись: два шага, предпросмотр и `tg_confirm`

Инструменты записи ничего не делают в Telegram сами (решения 4 и 23). Отдельного бота для согласований нет.

1. `tg_reply`, `tg_send`, `tg_react`, `tg_join`, `tg_rule_set` или `tg_task_start` возвращает предпросмотр: что будет сделано, с какого аккаунта, точный текст, и `approval_id`.
2. Агент показывает предпросмотр владельцу.
3. После согласия владельца агент вызывает `tg_confirm` с `approval_id`. Действие выполняет шлюз и сразу возвращает исход.

Правила:

- `tg_confirm text=...` заменяет черновик словами владельца. `action=reject` отменяет запрос. `action=list` показывает всё, что ждёт решения.
- Чужой запрос подтвердить нельзя: для другого пользователя его не существует.
- Повторное подтверждение действие второй раз не выполняет, а возвращает прежний исход.
- Запрос живёт 12 часов. После срока подтверждение ничего не делает.
- Текст до 4096 символов (предел Telegram). Невидимые символы убираются до предпросмотра: подтверждается ровно то, что уйдёт.
- Если шлюз перезапустился, пока действие выполнялось, оно не повторяется: исход `failed` с пометкой, что результат неизвестен.
- Агенту, запущенному без человека (по правилу или поручению), `tg_confirm` недоступен. Его черновик ждёт владельца: событие в `tg_inbox`, счётчик в `tg_status`, текст в `tg_confirm action=list` (помечен как чужой).

## core: чтение и поиск, включён по умолчанию

| Инструмент | Что делает | Методы MTProto |
|---|---|---|
| `tg_status` | Кто вызывает, какие аккаунты доступны, паузы FLOOD_WAIT (общая и по отдельным методам), включённые наборы | нет |
| `tg_list_dialogs` | Каналы и группы, где состоит аккаунт, вместе с архивом: фильтр по названию и типу, курсор. Личные переписки не показываются | messages.getDialogs |
| `tg_resolve` | Карточка чата по @username, ссылке t.me или инвайту | contacts.resolveUsername, channels.getFullChannel, messages.getFullChat, users.getFullUser, messages.checkChatInvite |
| `tg_search_messages` | Поиск по каналам (`where=channels`, по умолчанию) или группам (`where=groups`), где состоит аккаунт; личные переписки не ищутся. Запрос из одного #хэштега ищет по публичным постам | messages.searchGlobal, channels.searchPosts |
| `tg_search_chat` | Поиск внутри одного чата: слово, автор, даты, тема форума | messages.search |
| `tg_read_history` | Лента чата: курсор или окно дат, режим `brief` или `full` | messages.getHistory, messages.getReplies (тема) |
| `tg_get_message` | Сообщение по ссылке или id, пачка до 100 id, контекст до и после | channels.getMessages, messages.getMessages, messages.getHistory |
| `tg_get_comments` | Комментарии к посту: свежие, топ по реакциям, поиск по слову | messages.getReplies, messages.getDiscussionMessage, messages.search |
| `tg_list_topics` | Темы форума | channels.getForumTopics |
| `tg_export` | Выгрузка в JSONL или CSV: цены, тип объявления, превью фото. Возвращает путь, число строк и 5 примеров | messages.search, messages.getHistory, upload.getFile |
| `tg_get_media` | Фото, альбом целиком или превью видео; `thumb` или `full`; путь к файлу или картинка в ответе | upload.getFile |

## automate: наблюдение, правила, поручения

| Инструмент | Что делает | Нужен `tg_confirm` |
|---|---|---|
| `tg_watch` | Список наблюдаемых чатов: добавить, убрать, показать. Любой канал или группа, личные чаты наблюдать нельзя. Чат, закрытый владельцем, выпадает из списка | нет: наблюдение ничего не пишет |
| `tg_inbox` | События после курсора: новые посты, черновики запусков без человека, исходы подтверждённых запросов, запуски агента, вопросы и отчёты поручений | нет |
| `tg_rule_set` | Создать или изменить правило: чат, задание агенту, лимиты. `enabled=false` выключает сразу. Имена правил у каждого пользователя свои | да, кроме выключения |
| `tg_rules` | Свои правила и чужие на общих аккаунтах, лимиты, последние срабатывания | нет |
| `tg_task_start` | Начать поручение: собеседник, цель, рамки, что решает владелец, первое сообщение, срок, способ переписки | да, вместе с первым сообщением |
| `tg_task_get` | Цель, рамки, состояние и переписка поручения | нет |
| `tg_task_update` | `question`: вопрос владельцу (приходит в его `tg_inbox`); `answer`: ответ или указание владельца, передаёт только его собственный агент; `done`: отчёт и закрытие; `waiting`: ничего не писать | нет |
| `tg_tasks` | Список поручений; `stop` закрывает своё поручение сразу | нет |

## write: действия в два шага

| Инструмент | Что делает | Методы MTProto |
|---|---|---|
| `tg_reply` | Черновик ответа в комментариях к посту, от аккаунта или от имени канала. Один ответ на пост с аккаунта | messages.getDiscussionMessage, messages.sendMessage |
| `tg_send` | Черновик сообщения: собеседнику поручения или в открытый чат | messages.sendMessage |

| `tg_react` | Реакция на пост, сообщение или комментарий одним стандартным эмодзи; `remove=true` снимает свою. До 30 в день | messages.sendReaction |

## Агент, запущенный по правилу или поручению

Такой агент получает токен запуска. По нему видны только инструменты его дела:

- правило: `tg_status`, `tg_get_message`, `tg_get_comments`, `tg_get_media`, `tg_read_history`, `tg_reply`. Список чатов, поиск каналов, индекс и реакции такому агенту недоступны. Доступен только чат правила, ответить можно только на пост, из-за которого агент запущен;
- поручение: `tg_status`, `tg_task_get`, `tg_task_update`, `tg_send`, `tg_get_media`. Доступно только своё поручение и его собеседник, причём переписка видна с первого сообщения поручения: то, что было в этом диалоге раньше, агенту не показывается.

Задание, которое runner не забрал за два часа, снимается: агент не отвечает на устаревший пост.

Токен перестаёт действовать, когда runner сообщает исход запуска.

## discover: поиск каналов

| Инструмент | Что делает | Методы MTProto |
|---|---|---|
| `tg_find_channels` | Публичные каналы и группы по словам из названия или username. Telegram ищет по именам, а не по содержимому постов | contacts.search |
| `tg_similar_channels` | Каналы, которые Telegram считает похожими (по общим подписчикам). `depth=2` добавляет соседей трёх крупнейших | channels.getChannelRecommendations |
| `tg_forward_sources` | Откуда чат репостит: источники пересланных сообщений в последних постах, с числом репостов | messages.getHistory |

Найденные каналы сразу известны аккаунту: их можно открыть по @username или id без нового поиска. Без Premium Telegram показывает только часть похожих каналов.

## analytics: статистика канала

| Инструмент | Что делает | Методы MTProto |
|---|---|---|
| `tg_channel_stats` | Числа за период: подписчики и их изменение, посты в неделю, средние и медианные просмотры, охват (просмотры к подписчикам), вовлечённость (реакции к просмотрам), комментарии и репосты на пост, доля пересылок и рекламы, тренд просмотров, разбивка по неделям, топ постов | channels.getFullChannel, messages.getHistory |

Всё считается по открытым счётчикам, поэтому работает и для чужих каналов. Оценок и «вердиктов» нет: шлюз отдаёт числа, выводы делает агент (решение 7). Рост подписчиков Telegram отдаёт только админам канала, поэтому шлюз запоминает число участников по дням, когда видит его (`tg_resolve`, `tg_channel_stats`), и показывает изменение между снимками. В первый день изменения нет.

## index: локальный индекс

| Инструмент | Что делает | Методы MTProto |
|---|---|---|
| `tg_index` | Сложить сообщения чата в базу шлюза (`add`, по умолчанию за 90 дней, до 3 лет), показать индексы (`list`), удалить (`remove`). Повторный `add` дочитывает новое. Долгий первый запуск возвращает `job_id` | messages.getHistory |
| `tg_local_search` | Поиск по проиндексированным чатам без обращений к Telegram: формы слова и регистр не важны, все слова запроса должны быть в сообщении. Окно дат, один чат или все, курсор | нет |

- Поиск видит только то, что было в чате на момент последнего `tg_index`: в ответе указана дата последней дочитки.
- Слова короче трёх символов в индекс не попадают: они проверяются по найденным сообщениям, а запрос только из коротких слов не выполняется.
- Индекс чата на общем аккаунте виден всем его пользователям, удалить его может только тот, кто создал. Чат, закрытый владельцем, из поиска пропадает.
- За один запуск читается до 20 000 сообщений; большой чат индексируется за несколько вызовов, без пропусков.
