# Открытые вопросы

Решения здесь принимает владелец. Агент может предложить вариант с доводами, но не выбирает сам. Уже принятое записано в [decisions.md](decisions.md).

## Ждёт подтверждения владельца

Решения 20, 22 и 24 агент принял сам по ходу работы. Они помечены «предложено» и действуют, пока владелец не скажет иначе. Самые заметные:

- **Установка только из копии установщика под root и по sha коммита** (решение 22).
- **Индекс наполняется только по вызову и хранит тексты чатов в базе шлюза** (решение 24).

## Можно решить позже

1. **Premium у аккаунта агента.** Полнотекстовый поиск по всем публичным постам Telegram доступен только с Premium и дневной квотой. Нужен ли он?
2. **npm.** Публиковать ли пакет и под каким именем. `tg-mcp` в npm занят чужим пакетом. Открытие исходников не требует npm-публикации.

## Для открытия исходников

План и доводы: [open-source-plan.md](open-source-plan.md). Ни один из вариантов ниже пока не принят.

1. **Репозиторий и история.** Открыть текущий репозиторий после аудита или создать отдельный из проверенного снимка. Если понадобится очистка истории, разрешить её отдельно.
2. **Лицензия.** Выбрать лицензию и правообладателя после проверки происхождения кода; в плане предложены MIT и Apache 2.0.
3. **Первый выпуск.** Выбрать публичное название, способ установки, поддерживаемые системы и версии Node. Решение 14 о приватном репозитории менять явно; `private: true` может остаться при установке из Git.
4. **Публичные сценарии.** Согласовать работу с данными и демонстрации с учётом условий Telegram для ИИ, согласия соответствующих пользователей и применимости API Terms к шлюзу.
5. **Вклад и сопровождение.** Определить сопровождающего, правила внешних PR, защиты `main`, условия принятия кода и приватный канал сообщений об уязвимостях. Изменение автоматического push в `main` оформить как пересмотр решения 19.
6. **Язык.** Нужны ли английские материалы и какое изменение текущего правила о русской документации это потребует.
