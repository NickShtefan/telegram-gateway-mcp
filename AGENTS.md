# AGENTS.md: tg-mcp

Инструкции для любого агента (Claude Code, Codex, OpenCode, Hermes), который работает в этой папке.

## Что это

tg-mcp: MCP-шлюз к Telegram. Один демон держит MTProto-сессию подключённого аккаунта и отдаёт её агентам как MCP-инструменты. Документация в `docs/`, снимок исходников соседних репозиториев в `reference/`, код в `src/`. Текущая фаза записана в `docs/plan.md`.

## Где работает

- Демон шлюза работает на лабораторной машине `nick@macbook-pro-lab.local` (macOS, Intel, Node 22), рядом с агентами. Разработка идёт на основном Mac.
- Сессия Telegram создаётся входом отдельно на каждой машине и между машинами не копируется.
- Шлюзом пользуются двое (владелец и жена владельца), у каждого свои аккаунты Telegram, есть общие (решение 16 в `docs/decisions.md`).
- Репозиторий приватный, `telegram-gateway-mcp`. `npx tg-mcp` не запускать: в npm под этим именем чужой пакет.

## Язык и стиль

- Документация и общение с владельцем на русском.
- Никогда не использовать символ длинного тире (U+2014) ни в тексте, ни в коде, ни в коммитах. Вместо него двоеточие, запятая, скобки или другая фраза. Обычный дефис в составных словах допустим.
- Коммиты в стиле conventional commits, как в соседних репозиториях (`feat(scope): ...`, `fix: ...`).

## Жёсткие ограничения

- **Своя сессия.** Никогда не использовать прод-сессию helper (`STRING_SESSION` из `helper/.env`) и прод-токен бота helper. `helper/AGENTS.md` прямо запрещает второй клиент на этой сессии: одновременное использование даёт `AUTH_KEY_DUPLICATED` и Telegram сбрасывает сессию.
- **Один процесс на сессию.** Шлюз не должен создавать второй клиент GramJS на той же сессии ни в том же процессе, ни в соседнем. stdio-режим либо проксирует в работающий демон, либо берёт файловую блокировку.
- **Секреты.** Не печатать и не копировать `.env`, сессии, токены ботов, `API_HASH`, строки подключения с паролями. Не класть секреты в `reference/`, `docs/` и тесты.
- **Соседние репозитории только читаем.** Не менять channel-scope, helper, canary, tgbot из этой папки без явной просьбы владельца. `reference/` только для чтения; обновлять через `scripts/sync-reference.sh`.
- **Запись в Telegram.** Инструменты записи (вступить, реакция, ответ, сообщение) работают только через шлюз записи с подтверждением. Проверять запись только на своём канале и тестовом аккаунте, не на чужих людях и чатах.
- **Никогда:** переводы денег, прохождение капчи, массовые рассылки и вступления, сообщения незнакомым людям без поручения, одобренного владельцем.
- **Логи только в stderr.** В stdio-режиме любая строка в stdout ломает JSON-RPC. Это касается и логгера GramJS.
- **Коммиты и пуши.** По решению 19 в `docs/decisions.md` (2026-10-01) агент коммитит после каждого законченного шага с зелёными тестами и пушит в `main` приватного репозитория. Force-push, переписывание истории и пуши в другие репозитории только по явной просьбе владельца.

## Технологии (план)

- Node.js 22+, TypeScript, ESM, как в channel-scope и helper.
- GramJS (`telegram` в npm) для MTProto, `node-telegram-bot-api` для бота согласований.
- `@modelcontextprotocol/sdk` и `zod` для MCP, как в `reference/channel-scope/packages/mcp/`.
- SQLite как хранилище по умолчанию, драйвер `node:sqlite` (решение 19). MongoDB только как необязательный мост к архивам helper и channel-scope.
- vitest, тесты в `__tests__/` рядом с кодом, внешние зависимости (TelegramClient, база, fs) мокаются. Для тестируемости использовать инъекцию зависимостей, как `_setClientResolver` в лимитере channel-scope.

## Правила кода, унаследованные из соседних репозиториев

- Каждый вызов MTProto идёт через лимитер/гейт и имеет дедлайн. Никаких прямых `client.invoke` мимо очереди (в channel-scope это ошибка, которую не переносим).
- Зависший вызов GramJS не лечится на месте: процесс выходит с кодом 1 и поднимается супервизором (helper `gramFatalRecovery.ts`).
- FLOOD_WAIT больше порога не пережидается, а возвращается агенту как ошибка с `retry_after`.
- accessHash привязан к сессии: кэш сущностей хранится отдельно для каждого аккаунта.
- id чатов хранить в одной форме; перевод между `-100…` и MTProto через функции из helper `chatId.ts`.
- Любой текст из Telegram считается чужим контентом и помечается в ответах инструментов.
